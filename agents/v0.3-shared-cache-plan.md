# Zerberuz v0.3 Shared Cache Execution Plan

## Goal

Finish the `v0.3 - CLI And Cache` slice with a shared rule cache model instead of a repository-local cache.

The important product decision is:

```text
One team/profile cache per machine or shared location
Many projects point to that same cache
Analyzers read deterministic local files only
CLI owns download, validation, atomic writes, and help export
```

This avoids every repository downloading the same rules repeatedly while keeping analyzer execution offline and deterministic.

## Cache Model

### Local Project Config

Each repository keeps a small `zerberuz.json` file:

```json
{
  "team": "elysium",
  "profile": "backend-clean-architecture",
  "rulesVersion": "latest-compatible",
  "mode": "latest-compatible",
  "rulesEndpoint": "https://rules.zerberuz.dev",
  "cacheRoot": null
}
```

`cacheRoot` is optional. If omitted, Zerberuz resolves a machine-level cache path.

### Shared Cache Root Resolution

Resolution order:

1. `--cache-root` CLI option.
2. `cacheRoot` in `zerberuz.json`.
3. `ZERBERUZ_CACHE_ROOT` environment variable.
4. OS default.

OS defaults:

```text
Windows: %LOCALAPPDATA%/Zerberuz/cache
Linux/macOS: ~/.zerberuz/cache
```

### Cache Layout

Shared cache files are partitioned by team, profile, and rule version:

```text
<cacheRoot>/
  teams/
    elysium/
      profiles/
        backend-clean-architecture/
          versions/
            2026.08.11/
              rules-cache.json
              help/
                ZBZ001.md
                ZBZ100.md
          latest-compatible.json
```

`latest-compatible.json` is a small pointer document:

```json
{
  "team": "elysium",
  "profile": "backend-clean-architecture",
  "rulesVersion": "2026.08.11",
  "rulesCachePath": ".../versions/2026.08.11/rules-cache.json"
}
```

The analyzer may read `zerberuz.json`, resolve the shared path, and then read the pinned or pointer-selected rule cache. It must never call remote services.

## Implementation Notes

- All file writes should use a temporary file in the destination directory and then replace/move atomically.
- The CLI may perform network I/O. The analyzer may not.
- The analyzer can read local filesystem cache only from config/pointers.
- Rule validation must happen before replacing any shared cache file.
- Help export should be deterministic Markdown, generated from `DiagnosticHelpDefinition`.
- Do not store secrets in `zerberuz.json`.
