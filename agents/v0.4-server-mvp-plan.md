# Zerberuz v0.4 Server MVP Execution Plan

## Goal

Build the first useful Zerberuz Server: an ASP.NET Core API that serves versioned rule profiles, diagnostic help, rule validation, and response hash metadata for the CLI.

The server MVP should be intentionally small:

```text
In-memory profile store
Versioned rule payloads
Diagnostic help lookup
Rule validation endpoint
SHA-256 response metadata
CLI sync from server profile endpoints
```

Persistent storage, authentication, signatures, approval workflows, and audit history are future work.

## Endpoint Contract

### List Versions

```text
GET /api/v1/profiles/{profile}/versions
```

Response:

```json
{
  "profile": "backend",
  "versions": ["2026.08.11"]
}
```

### Get Version

```text
GET /api/v1/profiles/{profile}/versions/{version}
```

Response:

```json
{
  "profile": "backend",
  "rulesVersion": "2026.08.11",
  "schemaVersion": "1.0",
  "minimumEngineVersion": "1.0.0",
  "sha256": "...",
  "ruleSet": {}
}
```

The CLI should be able to sync this endpoint directly.

### Get Latest Compatible

```text
GET /api/v1/profiles/{profile}/latest-compatible?engineVersion=1.0.0
```

For MVP, return the newest registered version for the profile.

### Get Diagnostic Help

```text
GET /api/v1/diagnostics/{diagnosticId}
GET /api/v1/profiles/{profile}/versions/{version}/diagnostics/{diagnosticId}/help
```

The first endpoint searches globally across seeded profiles. The second searches inside an exact profile/version.

### Validate Rules

```text
POST /api/v1/rules/validate
```

Request body is a `RuleSetDefinition`.

Response:

```json
{
  "isValid": true,
  "errors": []
}
```
